## Why

The admin dashboard lacks a consistent notification system. Some flows show inline success/error text and others show nothing at all. There is no `MessageService`, no `<p-toast>`, no `NotificationService`, and no animations provider in `app.config.ts`. Every create/update/delete flow relies on component-local `this.error` / `this.success` properties instead of toasts, and most `.subscribe()` calls lack an error callback.

## What Changes

- Provide `MessageService` once globally in `app.config.ts` and add `provideAnimations()`.
- Mount exactly one `<p-toast>` (no key, high `baseZIndex`) in `AdminShellComponent`; remove any others if added later.
- Create a root-provided `NotificationService` with `success(detail)`, `error(detail)`, `warn(detail)`, `info(detail)`. Success life 3000ms, error life 5000ms. Summary text generated by the service.
- Replace inline success/error text on every create/update/delete flow with `NotificationService` toasts.
- Add missing success/error toasts to all CRUD flows across products, categories, brands, attributes, media, variants, inventory, orders, returns, coupons, shipping zones, CMS pages, and CMS banners.
- Ensure every `.subscribe()` has `next` and `error` callbacks; the error callback notifies the user.
- Extend the HTTP interceptor to handle global errors (401, 403, 5xx, network) once with an error notification; components handle validation and business errors only to avoid duplicates.
- Keep message strings in one constants/message map.
- Notify before `router.navigate` when a flow navigates after saving.
- Do not change UI layout, routes, or API contracts.

## Non-goals

- Per-client notification configuration or delivery history.
- New API endpoints or changes to the API contract.
- Order-status or other customer-facing notifications.
- Persisting toasts or a notification inbox.

## Capabilities

### New Capabilities

- `admin-notifications`: Single global toast notification system for the admin dashboard backed by PrimeNG `MessageService` and wrapped by `NotificationService`.

### Modified Capabilities

- `admin-dashboard`: All existing CRUD flows now surface success/error toasts through `NotificationService`.

## Impact

- `apps/admin/src/app.config.ts`: global `MessageService` + animations provider.
- `apps/admin/src/layout/shell/admin-shell.component.ts`: single `<p-toast>`.
- `apps/admin/src/core/notifications/`: new `NotificationService` and message constants.
- `apps/admin/src/core/http/auth.interceptor.ts`: global error notification for 401/403/5xx/network.
- All CRUD component files in `catalog/`, `inventory/`, `orders/`, `returns/`, `cms/`, `settings/`.
